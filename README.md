## ARCHITECTURAL ABSTRACT

**VeloRix Tournaments** is an industrial-grade native Android competitive gaming execution engine engineered for high-concurrency esports deployment across premier battle-royale and tactical simulation titles (Free Fire, Battlegrounds Mobile India). Architected under rigorous mathematical invariants of **Clean Architecture**, **Unidirectional Data Flow (MVI/MVVM)**, and **asynchronous non-blocking coroutine dispatching**, the platform orchestrates sub-second tournament slot allocation, zero-latency state synchronization across concurrent player clusters, time-gated cryptographic match credential distribution, and continuous 24/7 autonomous surveillance executed by a native **Gemini 3.6 Flash Neural Watchdog**.

## COMPILATION AND LOCAL REPLICATION PROTOCOL

### Hardware and Toolchain Requirements
- **Integrated Development Environment:** Android Studio Ladybug (2024.2.1+) or Meerkat
- **Java Development Kit:** OpenJDK 17 LTS
- **Android Target Platform:** API Level 35 (`compileSdk = 35`, `minSdk = 24`, `targetSdk = 34`)

### Build Execution Commands

1. **Clone the Repository Tree:**
   ```bash
   git clone https://github.com/VX-ANANT/Velorix-tournaments.git
   cd Velorix-tournaments
   ```

2. **Inject Infrastructure Identity:**
   Position the authorized `google-services.json` specification directly within the `/app` root directory.

3. **Compile Deterministic Binary:**
   ```bash
   gradle :app:assembleDebug
   ```
   Verified binary will be generated at:
   `app/build/outputs/apk/debug/app-debug.apk` *(mirror updated at `./app-debug.apk`)*

4. **Initialize Neural Watchdog Subsystem (Optional):**
   ```bash
   cd velorix-watchdog-bot
   cp .env.example .env
   # Inject TELEGRAM_BOT_TOKEN and GEMINI_API_KEY
   npm install
   npm start
   ```

## SECURITY SPECIFICATION AND DEFENSE MATRIX

- **Zero-Trust Access Control:** Database rule schemas enforce row-level identity encapsulation; clients may only read authorized tournament documents and update individual profile schemas. Match slot matrices require cryptographically verified server-side writes.
- **Client-Side Request Throttling:** Hardware-backed interaction cooldowns and transactional mutex locks prevent duplicate submission vectors under network degradation or intentional spam.
- **Credential Segregation:** Sensitive API tokens and runtime signing keys are strictly decoupled from version control via automated secret management injection pipelines.
